# 更新记录

本文件记录 `educational-video-visual-design` 的版本变化。版本号以 `SKILL.md` frontmatter 中的 `metadata.version` 为准。

## 记录规则

从 V0.5 起，每次修改该 skill 时必须同步更新本文件，并记录：

* 版本号与更新日期；
* 更新触发原因；
* 新增、修改或删除的规则；
* 涉及的文件；
* 完成后的验证结果。

仅整理历史记录、修正文案或补充说明，但不改变 skill 行为时，不单独提升 `metadata.version`。任何会改变设计决策、工作流程、输出格式或验收标准的修改，都必须提升版本号。

## 历史重建说明

V0.1—V0.4 没有独立变更日志，也没有 Git 提交或完整版本快照。以下记录根据当前任务的历史对话、V0.2 原始附件和 V0.4 可确认基线重建。

记录中的“用户明确指定”表示版本号或内容在历史对话中有直接依据；“根据对话重建”表示更新方向可以确认，但无法保证当时每次保存的精确边界和日期。

## V0.8 — 2026-08-26

本次更新来自对高质量参考课程的连续画面复盘。参考中的用户—大模型模拟对话并不是抽象关系图，而是一个具有具体输入、可见中间变化、具体输出和状态累积的最小运行案例；同时，其信息始终沿稳定方向进入同一舞台，没有散落成多个竞争区域。原有规则虽要求案例化和持续舞台，但缺少区分“关系示意”与“机制演示”的可执行标准，也缺少画面聚合度验收。

新增与修改：

* 增加“关系示意与机制演示”的区分，明确 `用户 → 大模型 → 回答` 不能独立承担机制讲解；
* 将最小案例强化为具体角色、具体输入、明确方向、可见中间变化、具体输出和状态累积；
* 增加“输入—处理—输出替换测试”，用于识别仍然过度抽象的伪案例；
* 增加案例状态继承规则，要求每一步写成“上一状态 → 本次唯一变化 → 新状态”；
* 增加单一语义主轴，明确核心问题、稳定舞台、主轴方向、信息来源、状态去向和唯一视觉中心；
* 明确新信息应进入已有舞台并改变当前状态，不在四角另起解释区；
* 细化卡片边界：同一角色、同一结构、同一轴线且具有唯一阅读顺序的议程、步骤或问题链可以使用统一容器；
* 禁止不同层级、不同关系的信息以多个同权区域散落，即使卡片数量不多；
* 在工作流程中加入教学案例来源标记，并要求案例不得提前引入后续概念或改变逐字稿顺序；
* 在分镜输出中增加语义主轴、稳定舞台、具体输入、具体输出、状态继承方式、唯一视觉中心、聚合度风险和案例运行性结果；
* 增加“案例运行性检查”和“语义主轴与画面聚合度检查”；
* 将 V0.7 完整快照保存到 `versions/SKILL-v0.7.md`。

涉及文件：

* `SKILL.md`
* `CHANGELOG.md`
* `versions/SKILL-v0.7.md`

验证：`quick_validate.py` 检查通过；当前 `SKILL.md` 版本号为 0.8；V0.7 快照版本号保持为 0.7 且不包含 V0.8 新章节。使用参考中的模拟对话进行语义回测：抽象的“用户 → 大模型 → 回答”会因缺少具体输入、中间变化、具体输出和状态继承而未通过案例运行性检查；“特别 → 特别得 → 特别得棒”的连续生成案例可通过；同轴递进问题条可按卡片边界保留，多区域散点布局会被语义主轴检查拦截。

## V0.7 — 2026-08-26

本次更新来自对第三镜“大模型”视觉替身的复盘：网状球体虽然具有技术感，但不能让观众快速识别“大模型”，说明原有“可识别性”要求仍缺少可执行验收方法。

新增：

* 增加“一眼识别测试”：隐藏名称后单独观看约一秒，仍应能识别对象类别；
* 明确发光球体、抽象网格、节点网络、线框、齿轮和电路纹理通常只能作为辅助技术纹理；
* 建立“可识别轮廓 + 克制的技术细节 + 明确名称标签”的视觉替身组合；
* 明确“大模型”应优先使用大脑等清晰主体轮廓，内部网络只承担数字属性表达；
* 增加素材来源优先级和外部素材授权记录要求；
* 要求记录素材本地路径、来源、作者、许可证、署名、下载日期和修改情况；
* 将一眼识别测试接入工作流程、分镜输出、完成检查和最高优先级规则；
* 将 V0.6 完整快照保存到 `versions/SKILL-v0.6.md`。

涉及文件：

* `SKILL.md`
* `CHANGELOG.md`
* `versions/SKILL-v0.6.md`

验证：`quick_validate.py` 检查通过；V0.6 快照版本号保持为 0.6；第三镜已使用项目内原创大脑 SVG 替换网状球体，Remotion 类型检查和 1950 帧关键帧渲染通过。

## V0.6 — 2026-08-26

本次更新来自用户对课程画面的进一步约束：主知识画面只显示对象、概念、关键词、必要数据及其关系，解释型文字由口播承担；此前页面中的底部总结句和关系说明句造成了重复阅读负担。

新增：

* 增加独立的“主画面文字准入与解释型文字禁用”章节；
* 明确允许上屏的对象、概念、动作、数据、关系和真实被处理对象；
* 禁止主谓宾解释句、底部总结句、结论条、口播复述和解释标签；
* 禁止模板默认文案、虚构状态文案和无来源界面填充；
* 要求完整问题优先压缩为对象、未知位置、问号或矛盾关系；
* 要求包含、流程、因果、转换、对比、否定、循环和一对多关系优先通过视觉语法呈现；
* 明确真实示例文本与解释文字的边界；
* 明确底部区域不设知识总结区，完整字幕只能进入独立字幕层；
* 增加五项文字准入测试和完成后的逐文字删除测试；
* 在工作流程、分镜输出格式、镜头检查和最高优先级规则中接入文字准入要求；
* 将 V0.5 完整快照保存到 `versions/SKILL-v0.5.md`，从本版本起执行历史版本归档结构。

涉及文件：

## V0.5 — 2026-08-26

本次更新来自对“网页首屏与逐字稿开头严重不符”问题的复盘。

新增：

* 明确逐字稿是严格同步任务中信息顺序的唯一依据；
* 增加开场约束，禁止用自创案例替换逐字稿开头；
* 要求视觉案例服从原文顺序，不能提前讲解后续知识；

## V0.4 — 根据对话重建，2026-08-26 前

触发原因：用户进一步指出，抽象技术对象不能只用文字说明，应适当使用相关素材参与知识表达，例如用大脑图形把“大模型”转化为可识别的画面角色。

主要变化：

* 要求视觉替身具有可识别性、相关性、准确性和连续一致性；
* 要求素材参与流程、关系或状态表达，不能只是文字旁边的装饰配图；
* 容易误导的隐喻必须保留名称标签或改用更准确的系统模块表达；
* 在工作流程、分镜格式和完成检查中加入视觉替身与素材要求。

说明：V0.4 是 V0.5 更新前 `SKILL.md` 中可确认的版本号和文件基线。

## V0.3 — 根据对话重建，2026-08-26 前

触发原因：现有教学网页呈现过于死板，出现信息卡片逐条堆叠；随后通过参考高质量科普视频，进一步确认需要用案例运行过程持续抓住注意力。

主要变化：

* 视频镜头化表达，避免信息卡片逐条堆叠；
* 一个镜头只解决一个核心问题、观点或关系；
* 内容放在画面中部安全区，使用大而简洁的屏幕文字；
* 同一知识段使用持续演化的解释舞台，而不是一句话切一页；
* 明确镜头切换条件、视觉节拍和注意力推进方式；
* 方框必须代表真实对象或状态，不能只是文字容器；
* 引入“问题—预测—揭示”结构；
* 最终复杂画面必须由时间逐步建立；
* 区分字幕层和知识画面的职责；
* 陌生概念、机制和流程优先通过可运行的最小案例场景呈现；
* 案例需要包含角色、对象、初始状态、触发动作、运行过程、状态变化、结果和概念回收；
* 增加镜头化、案例场景、持续舞台、视觉节拍、容器语义和视觉载体检查。
