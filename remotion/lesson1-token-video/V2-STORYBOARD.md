# 第 1 课 Remotion V2｜镜头页规划

V2 是配口播的视频版，不是静态阅读版。屏幕只保留关键词、关系和必要示例；详细解释由口播承担。

## 视觉风格

采用「课程视觉 S02｜知识映射卡片」的视觉语言：深海军蓝底、白色大字、粉色重点、青色/蓝紫/粉色斜线纹理、黄色关系箭头和边缘点阵。这里只继承 S02 的色板与图形语言，不沿用静态参考图的信息堆叠方式；镜头仍以居中大字和逐步动画为主。

## 排版约束

- 核心内容位于画面中部 80% 安全区。
- 主文字通常为 72–126 px，最低不小于 34 px。
- 每屏只保留一个主观点；中心文字原则上不超过 12 个汉字。
- 不放长段说明，不使用三列以上密集信息卡。
- 同一状态只发生一个主要变化；并列信息按口播依次出现。
- 顶部只保留轻量章节标签，底部只保留细进度线。

## 20 个镜头页

| 页 | 核心画面 | 屏幕文字 | 渐进动画 |
|---:|---|---|---|
| 01 | 输入与回答 | 一句话进去 / 一段回答出来 | 先输入，再箭头，再回答，最后提出问题 |
| 02 | AI 产品外壳与核心 | AI 产品 / 大模型 | 功能逐项进入产品外壳，最后揭示内部核心 |
| 03 | LLM 工作定义 | 学过大量规律 → 继续生成内容 | 名称、全称、左右两段能力依次出现 |
| 04 | 语境候选 | 充电器、充电宝、插座…… | 先给句子，再逐个出现候选，最后建立两种判断依据 |
| 05 | 生成循环 | 预测 → 生成 → 接回 → 再预测 | 环节逐项出现并转移焦点，最后收束为 Token 接龙 |
| 06 | 流式回答 | 每生成一个，界面显示一点 | Token 逐个进入回答框，最后否定“假打字” |
| 07 | Token 定义 | Token / 基本单位 | 先概念，再定义，最后只给出四个常见使用场景 |
| 08 | 误解纠正 | Token ≠ 汉字 / 单词 / 字符 | 三个否定项随口播逐项出现 |
| 09 | Tokenizer | 文字 → Tokenizer → Token | 原句保留，转换节点和 Token 块依次进入 |
| 10 | 不同切分 | Tokenizer A / Tokenizer B | 同一句话分流，先展示 A，再展示 B |
| 11 | Token ID | Token → 数字编号 | Token 卡翻面显示 ID，随后出现概念名 |
| 12 | 编解码 | 文字 → 编码 → 模型 → 解码 → 回答 | 从左到右逐节点建立，不提前显示完整链路 |
| 13 | Token 长度 | 没有固定答案 | 先提问与结论，再出现三类切分情况 |
| 14 | 真实样例 A | 中文原句与真实 Token 块 | 先原句，后逐块出现真实切分 |
| 15 | 真实样例 B | 中英混合原句与真实 Token 块 | 中文、英文、标点、emoji 的 Token 块逐步进入 |
| 16 | 容量误解 | 100 万 Token ≠ 100 万汉字 | 先左右两项，最后断开等号 |
| 17 | 实际影响 1 | 一次能处理多少 | 只讲上下文容量，不提前展示另外两项 |
| 18 | 实际影响 2 | 一次能生成多少 | 聚焦输出 Token 与回答长度 |
| 19 | 实际影响 3 | 一次调用多少钱 | 聚焦输入/输出 Token 与成本 |
| 20 | 完整链路 | 文字 → Tokenizer → Token/ID → 模型 → 解码 → 回答 | 逐节点复现，最后才引出 Context |

## 预览与正式成片的时间关系

当前 V2 是约 3 分 28 秒的压缩视觉预览，用于确认排版、镜头划分和动画语法。加入最终口播后，各镜头应按句级时间标记延长；元素出现顺序不改变，只调整停留时间。
