# 参考课程连续时间轴拆解（前 8 分钟）

对象：`references/参考课程_马克_视频.mp4`

方法：不是只看几张关键帧，而是按连续时间轴处理前 8 分钟：每秒采样、计算画面变化点，再结合参考文稿对齐旁白。重点观察“信息如何被引出、拆解、转场、收束”。

## 先给结论

参考课的信息可视化不是“每个概念做一张图”，而是：

```text
先抛出观众听过但不一定懂的词
↓
把它放在一个体系里
↓
每次只抓一个词出来解释
↓
解释完，把它变成后续可复用的锚点
↓
从这个锚点继续长出下一层概念
```

前 8 分钟的主线非常清楚：

```text
AI 新名词很多
↓
先从最底层 LLM 开始
↓
LLM = Large Language Model = 大语言模型 = 大模型
↓
大模型底层架构是 Transformer，但此处不展开
↓
大模型如何生成：文字接龙
↓
真实情况：模型不认识文字，只认识数字
↓
必须有 Tokenizer 做编码/解码
↓
编码 = 切分成 Token + 映射成 Token ID
↓
解码 = Token ID 映射回 Token
↓
Token 是基本单位，但不等于词
↓
用真实 tokenizer 演示反例
↓
总结 Token 的经验换算
```

这个顺序比我们的 V4/V5 里“为了视觉主线强行追踪一句话”更强，因为它始终贴着旁白的认知问题走。

## 参考课真正值得学的 7 条规则

### 1. 每段先建立观众的问题

参考课不是直接讲定义。

例如 Tokenizer 出现前，它先说：

> 模型本质上是数学函数，只认识数字，不认识人类文字。

这样 Tokenizer 的出现是“为了解决矛盾”，而不是新名词堆叠。

你的第 1 课也应该这样：

```text
文字接龙只是简化
↓
但模型不是真的接汉字
↓
那它接什么？
↓
Token
```

### 2. 新概念要从前一个画面长出来

`LLM` 长出 `Large Language Model`。

`大模型` 移出 `Transformer`。

`中间人` 变成 `Tokenizer`。

`Token` 映射成 `Token ID`。

你的 PPT 不能是：

```text
第 1 页：大模型
第 2 页：Token
第 3 页：Tokenizer
```

而应该是：

```text
大模型生成文字
↓
输出不是字，是一个个单位
↓
这个单位被命名为 Token
↓
正常文字要变成 Token，需要 Tokenizer
```

### 3. 复杂概念先只打开一层

Transformer 图出现后，参考课马上说“不用担心，不展开”。

这很重要。它告诉观众：

> 你只要知道大模型底层有这套架构，不需要现在看懂图。

你的课里也应该避免过度解释：

- Tokenizer 的具体算法不要展开；
- Token ID 的真实编号不重要；
- Encoding / Decoding 知道方向即可。

### 4. 例子出现的位置必须服务旁白顺序

参考课在解释“如何生成”时才出现“马克的视频怎么样”。

它没有一开头就用这个例子。

这正是 V4 割裂的根源：我们把“手机只剩 1%...”提前成全课主角，打乱了逐字稿。

### 5. 定义通常在过程之后出现

参考课不是先定义 Token，而是先走完：

```text
文字 → Tokenizer → Token → Token ID → 模型 → Token ID → Token
```

然后才说：

> Token 才是大模型处理文本的最基本单元。

你的课也应减少“先给定义页”，增加“先让过程发生”。

### 6. 反例要用同一工具连续演示

Token 不等于词这一段，参考课没有列三张卡片，而是连续在同一个 tokenizer 页面中换输入。

这样观众保持位置感：

```text
同一个输入框
同一个输出区
不同输入
不同切分结果
```

你的第（9）段应采用这个逻辑。

### 7. 每个阶段结束都要收束成一句可复用锚点

参考课每段讲完都会收束：

- LLM 简称大模型；
- 大模型底层引擎是 Transformer；
- 大模型是文字接龙；
- Token 是基本单位；
- Token 和词没有一一对应关系。

你的 PPT 每段也应该收束成下段能复用的视觉锚点，而不是直接切到新概念。

## 对下一版 PPT 的直接要求

V5 仍然不够的地方：

1. 逐字稿顺序对齐了，但页与页之间仍然偏“关键帧清单”。
2. 缺少参考课那种“先提出矛盾，再让概念解决矛盾”的节奏。
3. Tokenizer 段应该更长、更连续，因为参考课在这里用了完整的拆解过程。
4. 第（10）段不能只三页概括；需要从 Token 作为计量单位自然推到上下文、输出和成本。

下一版应改成 10 个“连续段落”，每段内部 3-6 个动作：

```text
1. 产品层 → 大模型
2. LLM → 大语言模型 → 大模型
3. 大模型生成：候选收敛 + 接回上下文
4. 为什么一点点出现：循环生成
5. Token：从输出单位抽象出来
6. Tokenizer：为解决文字/数字矛盾而出现
7. Token ID / 编码解码：同一链路双向转换
8. Token 不等于字词字符：同一 tokenizer 连续反例
9. 真实演示：输入框和切分区保持不变
10. Token 影响使用：计量单位 → 上下文/输出/成本
```
