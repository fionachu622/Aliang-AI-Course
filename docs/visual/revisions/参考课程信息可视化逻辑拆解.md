# 参考课程信息可视化逻辑拆解

## 先纠正方向

之前的样片 V1/V2 接近的是参考视频的“形式”：大字、少元素、文字变形、Token 移动。

但真正要学的是它的“信息组织逻辑”：

**不是把旁白内容做成漂亮画面，而是把观众的认知过程做成连续画面。**

参考课每一步都在回答一个观众脑中的问题：

1. 这个词是什么？
2. 这个缩写每个字母代表什么？
3. 英文全称是什么意思？
4. 为什么可以简称成大模型？
5. 大模型内部到底是什么结构？
6. 这个内部结构暂时要不要展开？

画面不是在“展示信息”，而是在“处理观众的困惑”。

## 参考课的底层逻辑

### 1. 先给观众一个未知对象

参考视频一开始只给 `LLM`。

这一步的作用不是装饰，而是建立问题：

> 观众现在只知道一个缩写，但不知道它是什么意思。

因此画面必须非常空，不能同时出现定义、结构、说明和例子。

如果一开始就放 `LLM = Large Language Model = 大语言模型 = 基于 Transformer`，观众就失去了逐步理解的路径。

### 2. 对未知对象做“最小拆解”

`LLM` 被拆成 `L  L  M`。

这一步不是简单动画，而是在告诉观众：

> 这个未知对象不是一个整体黑盒，它可以被拆开理解。

拆解动作本身就是解释。

### 3. 让解释从原对象里长出来

`L` 旁边长出 `Large`，第二个 `L` 长出 `Language`，`M` 长出 `Model`。

这比直接切到一行 `Large Language Model` 更好，因为观众不需要重新建立关系。

他看到的是：

```text
L → Large
L → Language
M → Model
```

即每个字母和每个词之间的一一对应关系。

### 4. 翻译不是字幕，而是层级切换

英文全称出现后，画面再变成“大语言模型”。

这一步的逻辑是：

> 先理解英文构成，再获得中文概念名。

如果一开始就给中文，观众可能知道“大语言模型”这个词，但不知道它为什么叫这个名字。

### 5. 压缩概念，降低后续表达负担

`大语言模型` 再压缩成 `大模型`。

这一步很重要，因为后续课程会反复说“大模型”。参考课没有直接说“简称大模型”，而是让画面把“语言”弱化，让观众看到：

```text
大语言模型 → 大模型
```

这是一种“概念压缩动画”。

### 6. 把解释过的对象移到一边，打开下一层

“大模型”移到左边，右边出现 Transformer 图。

这一步的逻辑是：

> 名字已经解释完，现在进入内部结构；但“大模型”仍然保留，告诉观众右边结构属于左边这个对象。

它不是突然换到一张 Transformer 图，而是从“大模型”这个对象向右展开。

### 7. 及时阻止过度深入

出现 Transformer 后，参考课会说“不用担心”“后面再讲”之类的内容。

视觉上 Transformer 只是被引出，不会立刻展开成所有细节。

这一步的教学价值是：

> 告诉观众这里有内部结构，但本节只需要建立位置感，不需要现在学完。

这是非常关键的节制。

## 抽象成可复用公式

参考课的信息可视化逻辑可以抽象成：

```text
未知对象
↓
拆成可理解的部分
↓
每个部分长出含义
↓
转换成观众熟悉的表达
↓
压缩成后续可复用的概念锚点
↓
锚点移位，展开下一层结构
↓
只展开本节需要的深度
```

这才是我们要迁移到第 1 课的核心。

## 第 1 课应该如何应用这套逻辑

第 1 课不是简单讲很多概念，而是要让观众理解一个核心对象的旅程：

```text
一句人能看懂的话
↓
变成模型能处理的单位
↓
进入模型进行下一步预测
↓
再变回人能看懂的回答
```

所以第 1 课的视觉主角不应该是“AI 产品”“LLM”“Token”“Tokenizer”这些并列知识点。

真正主角应该是：

**一段人类文字。**

所有概念都从这段文字的变化中长出来。

## 新的全课视觉逻辑

### A. 从熟悉对象开始：聊天框里的一句话

不是先讲 ChatGPT、DeepSeek、豆包，也不是先展示 AI 产品列表。

应该先让观众看到一个熟悉场景：

```text
聊天框
输入：手机只剩 1% 的电，我赶紧找……
```

画面问题：

> 这句话发出去之后，到回答出现之前，中间发生了什么？

这比“AI 产品背后是什么”更直观，因为它从观众每天都做的动作开始。

### B. 聊天框退后，只留下这句话

产品界面不是主角。

聊天框应该退后、变淡，留下输入文字。

画面逻辑：

```text
产品外壳退后
↓
输入文字留下
```

这一步告诉观众：

> 接下来我们不是讲按钮和功能，而是追踪这句话。

### C. 文字不能直接进模型，中间出现一道门

这时不要直接出现 Tokenizer 的定义。

让文字试图进入“大模型”，但在模型前停住，中间出现一道门：

```text
文字 → [ ? ] → 大模型
```

观众问题：

> 为什么中间需要一个东西？

这时再揭示：

```text
[ ? ] → Tokenizer
```

这样 Tokenizer 是从问题里长出来的，不是突然塞进来的名词。

### D. Tokenizer 的作用必须通过“切分动作”解释

文字条进入 Tokenizer。

出来时不再是整句，而是一块一块：

```text
手机｜快｜没电｜了｜我｜得｜找｜充电器
```

这一步必须是课程的第一个强视觉点。

它回答：

> Token 不是定义出来的，而是文字经过 Tokenizer 后产生的。

### E. Token 不是字/词/字符：用同一个切分器处理不同输入

不要用三张卡片写“不等于汉字、不等于英文单词、不等于字符”。

应该用同一个 Tokenizer 连续处理三类输入：

1. 中文句子
2. 中英混合句子
3. emoji / 数字 / 标点

每次输出的 Token 块数量和边界都不同。

画面逻辑：

```text
同一个动作，不同结果
↓
所以没有固定换算
```

观众会自己看出“不是一一对应”，而不是被告知。

### F. Token ID：不要新增概念，直接让 Token 翻面

Token ID 最好的呈现不是再画一条流程图：

```text
Token → Token ID
```

而是让刚刚切出来的 Token 块翻面，背后显示数字：

```text
手机  →  9854
快    →  124
没电  →  7741
```

这一步的逻辑是：

> Token 和 Token ID 是同一个单位的两种表示；不是两个完全无关的东西。

翻面比箭头更直观。

### G. Encoding / Decoding：用方向表达，不用定义表达

编码不应该先写 `Encoding，编码`。

应该先让路径发生：

```text
文字 → Token → Token ID
```

然后在这条路径上方扫出一个标签：

```text
Encoding
```

解码同理：

```text
Token ID → Token → 文字
```

再扫出：

```text
Decoding
```

观众先看到过程，再得到名称。

### H. 生成回答：不要用“概率条”，用“候选收敛”

上一版用了候选词和概率条，还是偏图表。

更接近参考逻辑的做法是：

例句停在省略号：

```text
手机只剩 1% 的电，我赶紧找……
```

省略号周围浮出几个候选：

```text
充电器 / 充电宝 / 插座 / 遥控器
```

然后不显示百分比，而是用运动表达概率：

- 高概率词靠近句尾；
- 低概率词远离并变淡；
- 最终“充电器”吸附到句尾。

画面逻辑：

> 模型不是查答案，而是在多个可能延续中收敛到一个。

### I. 一点点生成：把新 Token 接回上下文，再触发下一轮

不要只让 Token 一个个排出来。

必须表现循环：

```text
已有内容
↓
预测下一个 Token
↓
新 Token 接回句尾
↓
新的已有内容
↓
再预测
```

视觉上可以让句子末尾出现一个“预测环”：

1. 候选浮出；
2. 一个 Token 被吸附；
3. 整句向左轻微移动；
4. 末尾再次发光；
5. 下一组候选浮出。

这才解释了“为什么回答一点一点出现”。

### J. 上下文长度、输出长度、成本：都从 Token 计数自然长出来

不要突然出现三张卡片：

- 一次处理多少；
- 最多生成多少；
- 使用成本。

应该沿用同一个 Token 流：

1. Token 流进入一个容器，容器边界出现：这就是上下文长度。
2. Token 流从模型输出，出口处有额度条：这就是生成长度。
3. 输入 Token 和输出 Token 分别流向两个计数器：这就是成本。

所有影响都来自同一个视觉对象：

**Token 流。**

## 第 1 课新的核心视觉地图

不要一开始展示这张完整地图。

但制作时内部要有这张地图：

```text
聊天框
  ↓ 退后
输入文字
  ↓ 被拦住
Tokenizer
  ↓ 切分
Token 块
  ↓ 翻面
Token ID
  ↓ 进入模型
候选 Token 收敛
  ↓ 接回上下文
逐步回答
  ↓ 计数
上下文 / 输出 / 成本
```

这张地图的关键是：

每一个新概念都从前一个对象的变化中产生。

## 对后续制作的硬性规则

1. **每个画面只能有一个主对象。**
   - 不是一个主区域，而是一个主对象。
   - 例如：LLM、输入文字、Tokenizer、Token、Token ID、候选 Token、Context 容器。

2. **新名词必须先由画面产生，再显示名称。**
   - 先看到文字被切分，再出现 Token。
   - 先看到 Token 翻面成数字，再出现 Token ID。
   - 先看到方向过程，再出现 Encoding / Decoding。

3. **不要用卡片解释机制。**
   - 卡片只允许用于章节结论。
   - 机制必须通过对象变化表达。

4. **不要把并列概念同时端出来。**
   - “上下文、输出、成本”不能同时三栏出现。
   - 应该让同一串 Token 分别进入三个场景。

5. **不要把所有概念都做成按钮或胶囊。**
   - Token 可以是块。
   - Tokenizer 应该是动作装置。
   - 大模型应该是承接预测动作的空间。

6. **动画必须回答认知问题。**
   - 飞入不是为了好看，而是因为对象从哪里来。
   - 移动不是为了动感，而是为了让出下一层空间。
   - 放大不是为了强调，而是为了从整体进入局部。

## 这对样片 V3 的要求

V3 不应该再从 `LLM` 开始。

原因：第 1 课的主问题不是“LLM 这个缩写是什么意思”，而是“我输入一句话后发生了什么”。

更好的 V3 开场应该是：

```text
聊天框里输入一句话
↓
发送后，聊天框退后
↓
这句话被单独留下
↓
文字走向大模型，却被中间的未知门拦住
↓
门命名为 Tokenizer
↓
文字穿门后碎成 Token
```

这样才是迁移参考课逻辑，而不是复刻参考课形式。
