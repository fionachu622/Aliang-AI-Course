# 第 1 课可视化重设计方案

## 参考视频给出的真正方法

这段 `llm 动画.mp4` 的好处不在于画面复杂，而在于它把“概念解释”做成了“概念自身的变化”：

1. **先给未知符号**：屏幕中心只有 `LLM`，观众先面对一个需要解释的对象。
2. **拆开符号**：`L L M` 被拉开，暗示每个字母都有含义。
3. **补全含义**：字母旁逐步长出 `Large / Language / Model`。
4. **翻译与压缩**：英文含义变成“大语言模型”，再压缩成“大模型”。
5. **对象移位让出空间**：`大模型` 移到左侧，右侧引出 `Transformer` 内部结构。
6. **从名字进入结构**：不是突然换图，而是从“大模型”这个对象向右展开内部架构。

这套逻辑适合我们的课程：画面不能只是把逐字稿摘成卡片，而要让“文字怎么进入模型、怎么变成 Token、怎么生成回答”在画面里真的发生。

## 第 1 课的核心视觉命题

观众看完这一课，应该在脑子里形成一条动态链路：

**我输入一句人类文字 → 文字被 Tokenizer 切成 Token → Token 变成 Token ID → 模型根据已有 Token 预测下一个 Token → 一个个 Token 接回上下文 → 最后解码成人能看到的回答。**

最容易产生理解困难的地方有三个：

- “大模型”听起来像一个抽象名词，不知道它和 ChatGPT、DeepSeek、豆包的关系。
- “Token”容易被误认为“一个汉字”或“一个英文单词”。
- “一点一点生成”容易被误解成产品故意做了打字动画，而不是生成机制本身。

## 整体视觉结构

采用一个贯穿全课的空间系统，而不是每段换一套图：

```text
左侧：用户输入的人类文字
中间：Tokenizer / Token 化区域
右侧：大模型生成区域
底部：最终回答逐步出现
```

但初始不要一次展示全部。参考视频的方式是“从一个词开始，逐步展开”。因此本课开场也应该这样做：

```text
AI 产品
  ↓ 外壳退后
大模型
  ↓ 名称展开
Large Language Model / 大语言模型
  ↓ 进入内部工作流
文字 → Tokenizer → Token / Token ID → 预测下一个 Token → 回答
```

## 视觉锚点

全课固定保留三个核心锚点：

- **人类文字**：一条可读的输入句子，例如“手机只剩 1% 的电，我赶紧找……”
- **Tokenizer**：一个“切分器”对象，不要只是绿色卡片。它应该像一个会把文字切成块的门/闸机/切片器。
- **大模型**：一个较大的“生成空间”或“模型容器”，不要只是一个按钮。Token 进入后，在里面发生概率选择和逐步生成。

位置关系：

- 人类文字始终从左进入。
- Tokenizer 始终在中间偏左。
- 大模型始终在右侧或中右侧。
- 输出回答从模型下方或右下方逐步长出来。

## 视觉语言

继续使用用户指定的浅色系统，但要降低“UI 组件感”：

- 背景：纯色 `#f5f0f0`，不加纹理、不加装饰线。
- 主色：蓝 `#007AFF` 表示“输入 / 产品 / 当前主线”。
- 辅色：绿 `#34C759` 表示“转换 / 生成 / 正确理解”。
- 文字：深色 `#1d1d1f`，解释性小字用 `#6e6e73`。
- 强调方式：局部放大、移位、遮罩、淡出非重点，而不是增加卡片数量。

## 动画总原则

每一段都遵守参考视频的“概念变形”逻辑：

- 能用一个词变成另一个词，就不要切到新页。
- 能从原对象展开局部，就不要突然出现新图。
- 屏幕上不要同时新增 3 个以上对象。
- 大字用于正在被解释的核心概念，小字只用于辅助定义。
- 旁白念概念时，画面展示概念之间的变化，不把旁白整句搬上屏。

## 对上一版 PPT 的关键修正

上一版最大问题不是“没有动画”，而是信息表达仍然是 PPT 卡片思维：

- 把概念做成卡片，观众看到的是信息列表，不是概念变化。
- 把流程画成静态节点，观众没有看到文字真的如何变成 Token。
- 用多页模拟动画，但每页主要是“新增内容”，不是“原对象变形”。
- Token、Tokenizer、Token ID 没有被做成可运动、可变形的对象。

新方案要把这些改掉：

- `LLM → Large Language Model → 大语言模型 → 大模型` 必须像参考视频一样连续变形。
- `句子 → Tokenizer → Token → Token ID` 必须在同一空间内发生。
- `预测下一个 Token` 必须用候选词概率变化来表现，而不是只写一句定义。
- `一点点生成` 必须表现为 Token 接回上下文并触发下一轮预测。

## 建议的 PPT / Keynote 制作方式

如果继续做 PPT/Keynote，不建议只依赖单页内普通“飞入”动画。更适合采用：

1. **Keynote Magic Move / PowerPoint Morph**  
   用同名对象跨页移动、缩放、变形，模拟参考视频中的概念连续变化。

2. **一段内容拆多张关键帧页**  
   例如 `LLM → L L M → Large Language Model → 大语言模型 → 大模型` 至少 5 张关键帧，通过 Morph 串起来。

3. **Token 使用可复用对象**  
   Token 块必须是同一套图形对象，跨页只改变位置、颜色、文字和数量。

4. **减少卡片**  
   卡片只用于“总结性结论”，不能作为主要讲解载体。

5. **每 3～6 秒一个视觉变化**  
   不要让一张静态页停留 20 秒。参考视频几乎每半秒到几秒就有对象变化，但每次只变一个重点。

## 可删项

以下内容不建议作为主要画面：

- 大量白色卡片：会让课程像知识点清单，不像教学动画。
- 固定流程图长时间不动：可以作为总地图，但不能替代过程演示。
- 纯装饰背景线、纹理、进度条：对理解没有帮助，应删除。
- 把逐字稿整句放上屏：画面会重复旁白，反而降低注意力。

## 最终验收标准

这一版的验收不是“PPT 有没有动画”，而是：

- 观众是否真的看到 `LLM` 如何变成“大模型”；
- 是否看到一句话如何被 Tokenizer 切成 Token；
- 是否看到 Token 如何变成 Token ID；
- 是否看到模型如何根据上下文选择下一个 Token；
- 是否看到回答为什么是一个 Token 一个 Token 出来；
- 是否看到 Token 为什么影响上下文、输出和成本。

只有这些过程在画面中实际发生，才算接近参考视频的讲解感觉。
